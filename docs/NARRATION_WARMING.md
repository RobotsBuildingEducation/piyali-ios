Native narration can prepare one silent, receive-only Realtime connection before playback. Eligible foreground account entry prepares it only after the existing Firebase sign-in is available; playback refills one unused connection for the next request. Backgrounding, account changes and access changes clear unused preparation. Preparation sends no narration request, opens no microphone, and does not activate or change the playback audio session. Existing conversation and transcription transports retain their own audio devices.

The source pool supplies the four-minute expiry, 15-second connection deadline, 30-second retry backoff, default ash voice and exclusive claim behavior. Readiness requires both an open event channel and an audio receiver. A claim removes the connection from the pool before waiting, so two requests cannot share it. A stopped or cancelled claim closes its transport; unused-pool clearing cannot close a connection already owned by narration. Connection timeout and cancellation settle readiness even when an underlying HTTP exchange has not returned. Missing policies, unavailable identity, expired preparation and failed connections fall back to the existing ordinary narration path.

The custom native audio device drains idle decoded output on one stable OS thread without starting an AVAudioEngine or collecting a recording. On an actual playback claim it stops that drain, notifies the SDK of the output interruption, activates the playback session and switches to the normal speaker/capture path. Selected Story character voices use the original GA session.update event before the first item and response. The API permits changing the voice before the first audio response; see the [official client-event reference](https://developers.openai.com/api/reference/resources/realtime/client-events). The per-response source narration instructions remain attached to response.create. A connection that has spoken is never returned to the pool.

Completed local audio replay still takes priority over a prepared connection. Response completion, output-buffer stop and native drain continue to gate natural completion and cache promotion. Preparation itself never requests speech, completes an activity or awards XP. No implementation controls are added to the product screens.

The exporter executes the actual source pool against fake peers and a controlled clock for single-flight/exclusive ownership, retry backoff, expired claims and clearing only unused connections. Ten exact source voice-update events and all source constants are compared in native tests. All four exports reproduce byte for byte; [the manifest](reference/narration-warm-manifest.json) records the source hashes and case counts.
