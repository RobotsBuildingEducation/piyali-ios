# Nostr achievement collection

The native app uses the main web product's kind `30078` and collection addresses `learning-achievements`, `learning-achievements:nosabos` and `learning-achievements:robotsbuildingeducation`. It reads the same four relays. Restored events must have the learner's exact public key, a supported address and a valid Schnorr signature. Every responding relay's snapshot contributes records, including older versions held by different relays.

The collection keeps genuine records ahead of previews and retains the earliest genuine timestamp. Unknown legacy IDs and other-host records survive restoration and publication. Existing genuine higher-level/full-course awards recover earlier milestones; the shared capstone requires both genuine full-course records. A protocol metadata bundle supports this interoperability without adding external course routes to the iPhone app.

Restore runs after account boot. Publication requires the learner to enable **Keep my achievement collection public on Nostr** in Achievements. That choice is stored on this iPhone and stripped from cloud snapshots. Sharing updates confirmed awards automatically; Restore and Publish buttons also allow a deliberate sync. Turning sharing off cancels an in-flight operation. Switching accounts cancels the old account's relay work and discards stale callbacks. Overlapping requests serialize their reads/imports/publication and queued work rechecks the account before starting.

Before publication the app reads/merges the relay collection and includes awards confirmed while import was waiting. It publishes only to the Piyali host address and advances its timestamp beyond the stored Piyali event. The other host's address remains separate. A matching accepted event ID from at least one relay is required before reporting successful publication. Unrelated acknowledgements, malformed EOSE messages, rejected writes and timeouts do not confirm success.

The transport implements [NIP-42 authentication](https://github.com/nostr-protocol/nips/blob/master/42.md): it signs a current kind `22242` proof tied to the relay URL/challenge, sends it on `AUTH`, waits for its matching acknowledgement and retries the original operation. Authentication proofs are ephemeral rather than collection events. Signature/filter checks and address handling follow the [NIP-01 wire protocol](https://github.com/nostr-protocol/nips/blob/master/01.md).

Signed records are retained locally even if Firebase import is unavailable. Known protocol IDs merge into the independent Piyali Firebase project's private `achievements` collection. Legacy unknown IDs remain in the relay/local collection. Import preserves genuine timestamps, replaces previews when a genuine record arrives and grants no XP, curriculum completion or subscription entitlement. The original web Firebase project remains untouched.

Run `scripts/test-nostr.sh` for isolated Keychain identities and loopback WebSocket tests. These cover authenticated reads/publication, first accepted acknowledgement, unavailable relays, rejected/forged frames, collection union, legacy/other-host preservation, in-flight awards, unchanged-publication suppression and account-switch cancellation. The local test relay never broadcasts to public relays. Pure fixtures execute the actual reference merge/completion/event-template functions.

The read-only public-relay check passed locally. To repeat it, use `TEST_RUNNER_PIYALI_LIVE_NOSTR=1 scripts/test-nostr.sh`. It creates a fresh isolated key, reads its empty collection and performs ephemeral authentication if requested. It does not publish a collection or import anything into production Firebase.
