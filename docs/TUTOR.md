# Native Tutor correction in progress

The main Tutor menu and focused Goal/repair routes now open the native source-driven voice lesson. The main product no longer routes these focused sessions through the text form or the separate manual-check live form. The unused legacy Home/DailyPlate prototypes still contain their older adapter and need cleanup before those routes could be reintroduced.

The native course is exported by executing the reference's actual lazy `loadLearningPath` builder without writing into that checkout. It retains 8,750 lessons in 14 practice languages and seven levels, including the introductory unit, colors, launch modes, Tutor purpose, target forms and capability evidence. The ordinary skill-tree export remains separate. The source introductory record deliberately keeps raw `xpRequired:0`; Tutor's own source helper derives its 50-XP requirement.

`export-tutor-policy.mjs` extracts original pure declarations and prompt builders into an isolated JavaScriptCore policy. Swift owns the screen, transport, grading sequence and storage. Explicit snapshots replace React refs and store reads; no source UI, Firebase or provider code runs in the app. Manifests record source hashes and adapter boundaries. There are 501 source-executed comparisons covering introductory/regular content, prompts, agendas, quizzes, paths, voices, transcript matching, translations, reconnect state, every combination of completed Tutor levels, and course-summary denominators, and the original Goal/repair lesson builders. Fixture inputs use the same canonical key order as the Swift adapter because the source Goal prompt embeds JSON text.

The ordinary native flow now includes:

- Source lesson header, XP wave, orb, latest assistant bubble, translated phrase pairs, replay control, chat log and shared call dock.
- Source level/unit map and circular nodes; locked lessons remain previewable. The introductory preview has seven objectives. The actual source launch helper chooses game or voice; the main microphone Start always starts voice.
- An ungraded support-language welcome for a new introductory conversation, followed by its lesson kickoff. Fresh Start clears visible bubbles and retains prior conversation privately. Pause/Resume retains the visible transcript and mute choice; interrupted WebRTC output uses the source reconstruction instruction.
- Original local phrase checks and semantic judge prompts. Successful turns award 3–7 XP and independent Score; help, filler and uncertain results do not. Capability objectives require their own evidence even when a prompted warm-up phrase earns XP.
- Ordered agendas, XP-only repeated quiz rounds, capped own-lesson XP and a separate once-only completion bonus/Speak activity. Ordinary Tutor completion requires XP plus agenda; quizzes require XP alone. Legacy full-XP checkpoints can recover once. Games complete through Tutor's bonus path and cannot claim a skill-tree reward.
- Tutor access combines the highest unlocked Lessons/Flashcards course with earned Tutor progress. The selected browsing level stays separate. Completing a higher Tutor course proves earlier courses in that track; the earned language-specific unlock only rises. Stored course totals take precedence over the bundled lesson count, and missing counts remain distinct from server zeroes. Finishing the final lesson selects the next course while the completion review still describes the finished lesson.
- Completed lessons remain voice practice: ordinary successful-turn XP/Score continues, with no second completion bonus or Speak count. A separate session agenda lets regular lessons advance without reopening their canonical completion or restoring deleted drafts. The original completed-starter flag is included in the source policy snapshot.
- Canonical `tutorLanguageLessons` records with schema-2 agenda/quiz state and bounded private drafts. Native hydration reads the target’s saved Tutor levels together so browsing another level retains its existing work; the source uses per-level subscriptions, so read-cost optimization remains. Completion deletes agenda/draft fields, preserves unrelated document fields and retries the same completion receipt before advancing. Source progress remains separate from skill-tree Lessons.

Focused Tutor uses the original `buildTutorRepairLessonFromFocus` output, including `buildGoalLesson`, its separate `content.goal`, and the repair mini-plan. Swift supplies neutral curriculum-only decoder defaults without changing the raw JSON used by the policy. The focused lesson's level controls its prompts and voice transcription context, independently of the normal Tutor browsing level.

Goal Tutor accumulates 25 local session XP and uses the original action/rubric check through native Responses. Its successful turns retain ordinary 3–7 XP and Score; completion records one prompted production event for the routed Goal modality, without a Tutor-path completion, Speak count, or additional completion XP. Repair has a 12-XP target and can end earlier when the original judge returns `repairAdvanced`. Completion gives one 12-XP repair bonus and one Repair count, reinforces the note, and saves its actual evidence. XP-only completion without the demonstrated-repair signal does not invent successful evidence. Both sessions keep their own XP/agenda in the live controller; they never create a regular Tutor progress document or change its stored lesson/draft.

Completion waits for acknowledgment and retains one retry intent. The Goal router does not restart an unchanged activity when access changes; repair keeps the finishing step mounted until retry/acknowledgment, then routes the next step and updates the shared mode header. Neither focused Tutor session adds an individual lesson-complete/review dialog: the daily course owns its celebration. The actual source Tutor mounts no separate Goal/repair banner, so the native Tutor uses its lesson header for context too.

The root subscription gate now retains the mounted product instead of destroying it when free access ends. The Tutor registers earned work before the final turn/bonus changes account XP; its hold is scoped to account, practice language, and local day. Goal/repair parents preserve their child while saving. Ordinary completion and its review retain the hold until dismissal. Exiting the screen releases it, and a changed session scope clears stale presentation/retry state. Earlier trial tests covered only the inner controller or activity; the current rendered checks include the production root gate as well. Other modes' completion boundaries still need their own full root/guided audit.

The authenticated Piyali Cloudflare worker forwards bounded source ASR language/prompt hints while retaining the fixed transcription model, voice/model checks, App Check/authentication, rate limits and manual turn policy. Deployed worker version: `e7322cc5-8312-4c3e-83b4-5f266119a3e6`.
