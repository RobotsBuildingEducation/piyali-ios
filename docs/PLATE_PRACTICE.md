# Daily-practice sequencing checkpoint

The native product now uses the original web `App.jsx` plate conductor callbacks, exported by `scripts/export-plate-session.mjs`. The reference checkout is read-only. JavaScriptCore receives plate snapshots, modal blockers, a clock and Goal/repair descriptions; Swift owns navigation, saved session scope, dialogs and activity lifecycles. No React, DOM, browser storage or network runs in this policy.

Start tasks opens the first unfinished surface without connecting its microphone or starting an activity. Completing Tutor or an ordinary lesson first preserves its own completion sequence. The course dialog then offers Continue into the next unfinished surface. Intermediate repair steps route silently; Goal bundles still use their existing confirmed-modality progression. Standalone completion has no next-course route. Clearing a guided plate ends its saved session immediately, preserves the final activity behind the celebration, and returns home only on acknowledgment. View notes follows that same close path before opening Notes. The existing once-only 25-XP plate transaction remains responsible for the bonus.

The conductor retains the source hydration guard, completion keys, expected-modal grace period, quiet checks and deduplication. Scoped earned-result ownership keeps the mounted product available across the 300-XP trial boundary until Tutor, daily-goal, review and quest results have been acknowledged. A completed Conversation course stops its live session through the source course-complete action. Explicit account/language/day changes discard the prior conductor state.

Daily-goal rewards use the existing companion-health outcome and a newly queued local practice event. A goal reached during an active lesson appears without waiting for the whole lesson to end; the lesson remains mounted behind it. Tutor result → daily goal → Tutor review → course dialog is sequential. A late daily-goal reward waits behind an already visible course dialog. Local/cloud restoration is distinguished from newly earned work, including saved pending XP.

The course and whole-plate dialogs use source portraits 25/29, translated labels, the expandable what/why card, next-course icon, +25 card, Continue/Close and View notes. Daily Goal Complete uses the source copy and companion panel. Shared web theme rules supply the 48px modal corners, 28px mobile body inset, frame and pill controls. The source sparkle path/timing is drawn natively. Source quest note sequences/envelopes are exported as PCM; their sine-envelope rendering approximates Tone.js at 120 BPM. Native playback leaves the activity audio-session category untouched.

## Evidence and limits

The source manifest records the exact reference hashes, declarations, explicit adapters, original-conductor journeys and sound notes. Core checks execute the same source journeys in native JavaScriptCore. App-level checks exercise real learner mutations, modal ownership, bonus/trial retention, Notes release, hydration and language changes. Simulator product journeys begin at account creation and use normal product controls. Their narrowly scoped Debug fixture supplies a saved 47/50 Tutor checkpoint and prior lesson/review work, or a returning Conversation quest one goal from completion; timed transport events use the real Tutor classifier, completion and XP paths. No learner-only fixture buttons are added.

Visual evidence pairs actual source JSX in iPhone WebKit with native rendering in English/light and Arabic/dark. Companion and sparkle frames are animated, so frame poses can differ. These checks cover the celebration checkpoint, not full application parity. Further work remains on broad day-change/account recovery journeys, combined modal interruptions, all locales/device sizes/Dynamic Type, physical audio, and the separate designs and behaviors of Notes, settings, teams, wallet, RPG and subscription.
