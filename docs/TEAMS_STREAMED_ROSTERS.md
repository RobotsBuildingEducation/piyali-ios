## Source behavior and implementation

The original `TeamView` merges an existing team's subscription document immediately, then independently awaits member progress. Old member rows remain while that request is pending or fails. A missing document is ignored; the known-team subscription does not insert a new team. The original `teams.js` adapter delivers its first cached Firebase snapshot. Ordinary source document/query reads permit SDK cache fallback.

Native now consumes typed validated roster records directly, including cached first snapshots. A cached known roster attaches its watch before waiting for a fresh full read. Card title, pending members and display metadata update immediately; independent per-team member reads retain previous rows until successful replacement. A failed member read retains those rows without creating a source-absent error toast or erasing a management error. Ordinary read-only Firebase roster/invite/progress requests use default cache fallback. Private per-team progress reads can overlap without overwriting the service's shared selected-team progress state. Mutations retain their transactions and existing permission proof.

Unsigned mirror display changes cannot change the controller's team key, creator role, public/private kind or verified Nostr authority. Public member rows and management actions still resolve against verified signed service records. The native Arabic journey changes a mirror title while the signed member request is held, later displays fresh signed progress, then deletes using the original signed team record. It rejects unsolicited kind-1 notes. Legacy reads stay within existing roster/progress paths; they do not expose learner roots or change Firebase projects.

Native burst coalescing, latest-row/full-read reconciliation, grant-watch replacement, account/session fencing and close cancellation are explicit native adaptations. The original source callback oracle does **not** establish equivalent protection from already queued callbacks or late full reads. Unknown records, kind flips and old watches cannot insert or reauthorize a team. Display-only updates do not schedule a new progress publication.

Team and member view identities now remain stable across JSON changes. Pending identifiers follow original spacing/colors. Tabs scroll inside the drawer body as in the actual source; the handle, title and physical close control remain in the fixed header.
