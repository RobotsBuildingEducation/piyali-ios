# Curriculum session correction

Ordinary curriculum lessons now open one active engine, with their saved lesson-owned XP and module controls visible. Grammar/vocabulary Next and Skip hand off to another available activity rather than remaining in the old generic skill checklist. Reading and stories can participate without dismissing the lesson when their review finishes. Reading/story screens still need deeper interaction/design corrections. Realtime now uses a native source-goal voice activity; see [the realtime checkpoint](REALTIME_LESSON.md).

Reaching an ordinary lesson's own goal commits the authored completion bonus once, returns to the path and presents the original completion copy, character artwork and purple gradient. Completion presentation blocks the daily guided-task celebration until Continue closes it. This is initial sequencing infrastructure; full daily-goal, introductory Bitcoin, repair/goal and all guided-session combinations are not yet verified. Games retain their existing flow. Final quiz entry retains the existing dedicated assessment component, pending its typed-question port; quiz contracts cannot award practice XP.

The iPhone UI test completes the actual first Spanish curriculum lesson (`My Family`, 80 XP). It completes the existing introduction, starts from the lesson preview, answers two questions without prematurely completing, continues through fourteen distinct six-XP question instances across the two authored modules, observes the separate +80 bonus, continues to the path, verifies the next node unlocks, and confirms completion persists after relaunch. It uses isolated offline question data, not real learner answers or a fake product shell. Native live-provider question contracts were checked separately.

Additional checks cover source judge behavior, quiz reward exclusion, counter/import/rebase rules and question persistence. The simulator suite prefers a separately created `Piyali Parity QA` iPhone when present; `PIYALI_TEST_DEVICE` overrides that choice. The user's regular simulator account stays separate. Microphone capture now creates its audio engine only after the user requests recording and permission is available; physical-device audio remains a required check.

Getting Started now mounts the six engines inline with the original stepper labels/colors and automatically presents completion after the last activity. The next work includes the original voice transport and audio interactions, assessment and curriculum context for the remaining engines, typed final quizzes, remaining feature panels and complete product design parity. This checkpoint does not establish completion of the port.

Grammar/vocabulary and curriculum realtime now save source difficulty quotes and apply them to progress; see [the assessment checkpoint](QUESTION_WORTH.md).
