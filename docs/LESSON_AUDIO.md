Playback belongs to an account/language/lesson/question scope. A new request closes the previous transport; changing question, skipping, checking, starting recording, opening the deck, losing access, backgrounding or leaving the screen cancels it. Late provider events cannot restart old audio. Completion still requires successful generation, output-buffer stop and native playout drain. The transport never enables a microphone for narration. A failed request clears its loading state and allows retry. Repeated taps while a lesson-card answer is loading leave that original request running, as in the source; other question taps restart narration. Starting playback cancels capture without canceling an already submitted grading task.

Standard, translation/repetition and speaking controls now show the source loading spinner; matching shows it only for the selected word and tapping that word again cancels loading. Lesson-card controls show loading and active playback. The source's speculative browser warming and recorded replay cache are not ported here, so repeated playback establishes a fresh native narration connection. Advanced/writing controls use their existing native playback treatment; exact per-exercise loading/motion fidelity remains open.
