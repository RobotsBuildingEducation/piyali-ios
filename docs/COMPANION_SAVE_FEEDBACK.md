# Companion save feedback

Saving from Home, Goal Manager or Equip now starts the web product’s independent companion write after applying the name/type locally. The editor closes immediately. An actual write failure displays the original localized “Save failed” title and SDK description in a nonblocking bottom toast for five seconds. The selected companion and name remain intact. Saving an unchanged draft still submits one intent, matching the original callback.

The direct write shares the same settings receipt as the durable native outbox. Each immediate request confirms its older unacknowledged companion receipts before its own, preserving intent order across overlapping requests and snapshot retries. An unrelated practice/snapshot failure cannot produce a companion error, and background retries do not reissue a visible error for an old intent. A successful direct write only updates the canonical companion fields, the source `updatedAt` timestamp and receipt metadata. Retrying its receipt through either transport cannot undo a newer web choice or timestamp. Other settings, typed foreign fields, membership, XP and health remain intact. Restoring pending work is quiet. Keep current does not submit a customization request.

Feedback belongs to the account and support language captured when Save was pressed. Account changes cancel pending feedback and hide existing notices; a noncooperative old request cannot show its error under the new account. Notices are session state and never enter the learner snapshot. The native portal is a separate non-key window above nested editors. It cannot become key, passes touches outside the notice, and absorbs touches within its own rectangle like the web toast. Temporary root detachment during a full-screen cover does not hide it. Controls outside the notice remain usable; covered footer controls become available when it expires.

The toast follows the original Chakra layout: bottom safe-area placement, 8-point outer margin, a 300-point minimum/560-point maximum width, original warning SVG, red solid surface, white 16-point title/description, 24-point line boxes, source padding and rounded corners. ASCII HTML whitespace is collapsed for display, including leading newlines returned by Firebase rule errors; the original SDK description remains available in the notice state. This avoids inventing a blank line that the web does not render.

## Remaining scope

These checks establish the stated save/feedback behavior and selected layouts. Wider locale/device-size states, exact entry/exit and stacked-toast motion/shadow calibration, native announcements under physical VoiceOver, hardware-keyboard interaction and physical-device background/route behavior still need broader verification. The original unmodified source is the reference, and these checks do not establish full product parity. Firebase/Cloudflare deployments remain unchanged. See [the full audit](PARITY_AUDIT.md).
