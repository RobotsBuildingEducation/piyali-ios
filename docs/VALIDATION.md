# Native implementation validation

Verified locally with Xcode 26.4.1 / Swift 6.3.1 on an iPhone 17 Pro simulator running iOS 26.4.1. The minimum deployment target remains iOS 17.

- `swift test`: **38 tests passed**, including all 14 bundled curricula, 1,150 flashcards and 1,190 phonics decks, daily reset/streaks, language-specific XP, idempotent lesson rewards, answer normalization, persistence/migration, companion unlock rules and performance score boundaries. The scheduler test compares **116 cases** exported directly from the reference web algorithm, covering learning steps, hard/easy intervals, graduation, legacy records and lapses. Additional tests cover offline calendar days, in-flight practice/preference edits and zero-XP answer reveals. Six memory tests cover deduplication, preserved enrichment, language isolation, reinforcement, expiry/caps, in-flight captures and support-language changes and acknowledgment of practice/memories already committed by overlapping sync requests.
- Xcode `PiyaliTests` with the local Firestore emulator: **20 tests passed, one opt-in live API test skipped**. Identity/signature and subscription/auth challenge tests verify the native proof contracts. Sixteen exercise the real Firestore SDK and native sync service against copied reference rules: first account upload, shared XP visibility, duplicate retries, concurrent lesson completion, scheduler graduation/restoration, offline calendar history and stale preference requests, companion memory merges/retries, concurrent captures and shared reinforcement. Existing subscription fields, unrelated web settings and migration markers survive these writes.
- Xcode `PiyaliUITests`: **3 UI tests passed**, exercising offline account/onboarding, answer reveal and persisted review scheduling after terminating/relaunching, flashcard navigation, wrong-answer memory capture/persistence, note creation/persistence and the locked tutor screen. The placement flow also verifies selecting a starting level, persistence after relaunch and zero XP/completion grants. A third test saves a Spanish goal, switches to French without inheriting it, relaunches and restores the Spanish goal.
- `npm test --prefix BackendReference`: **4 tests passed**, accepting the web and native App Check IDs and rejecting unrelated IDs, wrong audience and expired tokens.
- Placement tests cover strongest self-report selection, lower course levels for proficiency ranges, separate lesson/card unlocks, language isolation, no XP/completion grants, earned Score preservation, stale placement rejection and in-flight changes. Firestore tests verify placement before offline graded work, retry idempotence, retakes and restoring course summaries/selected levels.
- Daily goal tests match 40 web modality-selection cases, the shared evidence format and a successful completion executed by the reference web source. They cover edit/pause/replacement, first saved plan wins, day rollover, observed completion without extra XP, duplicate preparation rewards, preparation without production credit, bounded summaries and sync while new practice is in flight. Real Firestore SDK tests exercise concurrent proposals/mode completion and shared `questDays` preparation artifacts, canonical profile creation after a first goal upload and whole-field replacement on day rollover.
- `git diff --check`: passed.

Run the isolated emulator suite with `scripts/test-firestore.sh` (Firebase CLI and Java 21 required), or start the emulator and run `TEST_RUNNER_PIYALI_FIRESTORE_EMULATOR_TESTS=1 scripts/test-ios.sh` for the complete simulator suite. The wrapper chooses an available iPhone simulator; `PIYALI_TEST_DEVICE` can select a UDID. `PIYALI_SOURCE_PACKAGES` optionally reuses an existing Xcode package cache. CI runs the core/backend tests, simulator build and opt-in Firestore suite.

The demo project is `demo-piyali-ios`, with Firestore at `127.0.0.1:8180`. Tests create a named Firebase app using emulator-only configuration and a test-only App Check provider. They do not initialize the production Firebase app, disable production App Check, deploy rules or write to a production database. A simulator configuration issue was fixed by assigning the local host before disabling SSL; no compiler workaround or deployment-target change was retained.

Xcode simulator tests must use ordinary/ad hoc signing (`CODE_SIGN_IDENTITY=-`). Disabling signing caused Keychain error -34018; signed runs pass. No in-memory fallback or Keychain bypass was added.

The independent `piyali-ios` Firebase project, custom Nostr authentication bridge, protected Firestore rules and separate Cloudflare worker are deployed. Opt-in live verification passed native sign-in/App Check debug exchange, Gemini text/JSON, native daily goal proposals and action-based goal checks, authenticated Responses exercises and Gemini Live PCM audio with goal instructions. Signed web restoration denies an unlinked account and rejects replay. Production App Attest awaits an enrolled Apple Developer account; paid Patreon membership, StoreKit purchases, relay publication and physical-device microphone/playback quality remain verification boundaries. The reference checkout and existing web backend were not modified.

Snapshot-only manual notes/history, full pet health decay and achievement reconciliation remain outside the shared-progress contract tested here. The feature boundaries in README still apply.

The reference repository retained its pre-existing change to `nosabos/src/components/LinksPage.jsx`; this task made no edits there.
