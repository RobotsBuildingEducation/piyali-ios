# Native achievement transcript and delivery

The main product’s achievement collection is a centered modal with Piyali and Robots Building Education tabs, completed/locked card grids, source series order, localized counts and a fixed collection progress footer. Its mobile inset, Close position and footer padding follow the actual global source theme overrides; paragraph labels use explicit document direction and greedy wrapping. Its complete catalog contains 104 permanent awards: 75 Piyali, 28 Robots Building Education and one shared final award, giving tab totals of 76 and 29. Displaying cross-platform awards does not add external course routes to the iPhone app.

`export-achievement-transcript.mjs` executes the original catalog, localization and grouping functions. It exports all ten authored locales, source theme dictionaries, number formatting, twenty character expressions/patterns and the original twenty-one reaction policies. Native completion display uses the existing validated saved records, with the source’s collected/locked partition. It does not award from XP, placement or displayed counters. Existing Firebase progress verification, permanent document IDs and Nostr ownership/signature checks remain responsible for awards.

Today’s Focus opens the native collection directly. The underlying menu is isolated while the modal is shown. Tabs, scrolling, Close, outside dismissal and the fixed footer remain native SwiftUI controls. Opening restores signed records without publishing; the saved publication preference and explicit restore/publish controls remain in Account’s secondary Nostr sync section. An actual local write failure raises the source storage warning until a successful retry. Provider failure retains the local collection.

The orb renderer uses the original eye arrays, palette material values and GLSL pigment fields translated to Metal, with the achievement collection’s wider camera/shadow frame rather than the compact Tutor frame. Award styles are opt-in parameters on the existing native sphere; Tutor and Conversation defaults retain their own visuals. Character reactions and the visual-only voice envelope use the original pure JavaScript policy through JavaScriptCore. Switching back to a Tutor orb restores its camera, material and default shader. Reduced Motion stops character and wave animation; backgrounding stops the renderer’s display link.

## Earned-award delivery

Confirmed new Firebase awards now enter a session-only FIFO queue. A transaction returns whether it actually created or upgraded the award; only its committed result emits delivery, outside the retryable transaction closure. Optimistic snapshots, cached reads, imports, ordinary restoration and initial backfill stay quiet. Concurrent saves cannot replay the same creation, and an earlier successful award still delivers if a later sync operation fails. No delivery callback grants XP.

The original web product uses `QuestionActionArea` for this feedback rather than an automatic modal. Native delivery replaces the current footer—or provides its Home fallback—with the original gold Continue row, localized title/description, 84-point character and transparent menu trigger. Continue and Close dismiss only the current award. Switching modes retains the queue and underlying activity state; dismissal restores that activity’s own controls. Inline typed/Realtime actions hide during delivery. Changing support language updates the copy; switching accounts or signing out clears the queue; relaunch restores permanent records without restoring celebrations.

Motion-disabled characters keep a cached full-resolution native render with transparent corners. The live scene stays hidden beneath that still, avoiding a blank first frame or doubled shadow. A later character, palette, state or size change refreshes it without running an animation loop.

The collection’s pending indicator now includes the existing native cloud outboxes and cloud failure state as well as active relay restoration. This does not yet reproduce the web app’s complete per-channel durable retry lifecycle.

Provider and storage tests use isolated identities and local fixtures; no production awards or public relay records are issued by the UI checks. The delivery journey uses an explicitly opted-in, UUID-scoped named `demo-piyali-ios` Firestore emulator: four committed progress events are seeded, then an actual graded/rated flashcard writes the fifth event and earns its award through the production sync/publisher/UI path. There is no injected celebration callback or synthetic award record in that journey.

The renderer’s lighting, compositing, random flow phase and geometry still require visual calibration against the WebGL reference. In the Arabic component fixture, the source Chakra portal leaves the menu trigger on the left while the action row reserves space on the right; the native menu follows logical right-to-left placement. That portal alignment still needs checking against the complete web shell. Wider locales/device sizes, long-session animation performance, physical-device VoiceOver, complete per-channel pending-sync/retry persistence, lost-response delivery and mixed modal/interruption recovery comparisons remain open. The larger functional/design parity goal is active. This checkpoint does not change the reference repository or deploy Firebase/Cloudflare.
