# Paper & Pencil entry and setup

The current reference opens Paper & Pencil when the App mounts, including before onboarding. Closing it over onboarding only changes the mounted open state; it does not acknowledge setup or open placement. After onboarding, the companion's Continue action can therefore show the suggestion again. In the product branch, closing it records the account-wide paper acknowledgment and continues to install/key guidance or the mounted-session placement gate. Returning mounts also start with Paper & Pencil, even when setup was already acknowledged. Native keeps that initial flag in RootView, separate from durable learner state, and passes it to the product conductor.

The previous animated SVG notebook, floating pencil, sparkles and header emblem are no longer rendered. SwiftUI now uses the exact `paper_pencil_manga.webp` bytes from the read-only reference (960×448), the original copy resolver for eleven locales, the icon-free teal header, source responsive artwork limits, small-phone body scrolling, rounded frame and shared backdrop. The image is decorative for accessibility. Original source line boxes are measured in iPhone WebKit; its fractional CSS line heights round down, and global modal CSS supplies extra bottom padding. Landscape uses the source larger header/body/button layout. Native does not embed the web modal at runtime.

Understood, backdrop taps and accessibility escape use the same close action. Body taps keep the modal open. Onboarding's controls are inaccessible while the modal is present. The original deferred action notes/timing are rendered as bundled sine PCM with source sound preference/volume; the envelope approximates Tone.js and is not an acoustic-identity claim. Earlier SVG/motion assets and captures are historical evidence, not the current illustration.

Product acknowledgment still writes only `paperPencilModalShown: true` (or `gettingStartedModalShown: true`) and `updatedAt` to the canonical owner document. Local-first flags, monotonic import/rebase, stale-account fencing and retry remain unchanged. This does not award XP or flush unrelated earned work. No backend/rules deployment is needed.

## Reproduction and evidence

Run `node scripts/export-paper-pencil.mjs` to regenerate current copy, static artwork metadata and original action notes, and copy the unmodified WebP. Run `node scripts/export-paper-pencil-entry.mjs` to execute the original App initializer/onboarding-close/product callbacks for all eight paper/setup/placement flag combinations, with only public state, persistence and paint adapters. Their source hashes and scope are retained in `docs/reference/paper-pencil-entry-manifest.json`.

Run the target-owned preview with `node scripts/start-reference-preview.mjs`, then opt into `PaperPencilReferenceTests` on the separate QA simulator. It renders the actual original modal at 320×568, 375×667, 402×874 and 874×402 in English/light and Arabic/dark, checks the absent SVG/icon, body-click behavior and original Understood callback, and compares native panel dimensions. Export attachments only after the result becomes terminal, then run `node scripts/import-paper-pencil-art.mjs <attachments-directory> <result-name>`. The current 32 image/metric records and asset hash are in `docs/reference/paper-pencil-manga-captures.json`.

The first build fails because two @State properties shared a declaration; the second collects all eight comparisons but exposes missing global padding and different text line boxes (19.580s). The third does not run tests because the legacy SmokeTests class needs MainActor isolation for the new real-modal entry helper. Run4 passes all eight corrected comparisons (16.788s), all three copy/entry checks and existing entry/onboarding journeys, but exposes background onboarding controls through the modal. Run5 passes the same four component/source checks (16.384s), the complete English first-run/relaunch flow (79.735s), and the Tutor replay regression through the new entry step (93.241s), while its Arabic backdrop test exposes blocked outside taps. These containing runs remain retained failures; they are not reported as overall green.

`PiyaliMangaPaper6.xcresult` passes all six final checks without failures or skips: all eight source/native comparisons (16.143s), three native copy/asset/entry checks, and complete English (79.641s) and Arabic (56.466s) product journeys. The final backdrop hit test uses the actual centered rounded-panel bounds, keeps body taps inside, and protects onboarding controls. All 40 final image/metric hashes match; every comparison and all eight product states were visually reviewed. Broader dynamic type/VoiceOver, modal opening/closing motion and other product surfaces retain their separate remaining work; this screen does not establish full app parity.
