# Connected-room exploration correction

The old native `ExplorationView` was a form of coordinates, compass buttons, “Walk to” teleport actions and a world-family/object-search picker. The source `RPGGame/index.jsx` displays the world itself. Its selection screen has one Generated World button. Native now uses the shared SpriteKit renderer, original source map/item art, one-tile canvas movement, automatic doorway entry, anchored characters, quest progress and map-based object/gather collection. Inventory, quest and companion controls sit over the map. The web repository remains read-only.

This is a legacy-renderer checkpoint. Current normal course, intro and Tutor game launches use the authored episode path. This change does **not** add an exploration item to the root product menu or establish that the source's legacy generation/fallback routing has been reproduced. The old standalone `RPGLibraryView` utility still owns its existing exploration link. Main-product routing and the source's fallback conditions require a separate audit.

## Source and saved behavior

- `scripts/export-exploration-content.mjs` executes the original fallback world and quest builders. The 224 bundled templates contain 448 distinct room geometries across two base languages, seven levels and eight environments. Each room now retains its exact world key; older saved rooms without that optional field resolve by their full saved geometry.
- `scripts/export-rpg-art.mjs --exploration` uses the original ground/tile/prop/item drawers with the established fixed art seed. It exports a separate `exploration-art.json.gz`, 448 room plans and 39 item sprite identities. The existing 443 authored map entries remain unchanged. Unreferenced files from an interrupted first export were removed before the checkpoint.
- `scripts/export-exploration-controls.mjs` extracts and executes the actual source `moveOneStepToward` closure. Its 3,108 public-data fixtures include primary/secondary axis movement, walls, fixed NPC collision and portal spawn handoff.
- An exact prop tap examines it without moving. Search items require the current search to have started, are assigned by the existing source rotation, cannot be collected twice, remain in inventory after an incorrect hand-in, and become available at their source after dropping. Completing that search clears its leftover decoys and collected keys.
- Correct hand-in displays the source success copy for 450 ms before completing its chapter. The pending success survives serialization; its scoped SwiftUI task rejects a cancelled/changed run. Closing the dialogue before acknowledgment does not strand that earned success. No legacy exploration action grants lesson XP or modifies subscription entitlement.
- Source observation prompts, parsing, pending state, cache sharing and 3.6-second dismissal now use the already verified `RPGObjectController`. Search pickup remains separate from observation generation. Account/language/map/background changes cancel the old observation owner.
- Music uses the same canonical version-2 settings update and original loop as authored games. NPC dialogue uses the existing character-aware narration service, with scoped shutdown on close/background/account changes; physical playback is not established by offline captures. Native microphone input retains an optional typed response and automatic submit when a deliberately armed recording stops.

## Validation

The focused Swift package selection passes all **nine exploration checks** in **25.701 seconds**, including the 3,108 actual-source movement/door cases, old-save geometry lookup inputs, wrong-item/drop/re-search behavior, serialized pending success, cleanup and unchanged XP. The first seven-test selection passed before the new interaction checks were added.

`PiyaliExploration2.xcresult` compiles the new native surface and passes both resource checks: every legacy room/item texture (**3.588s**) and every previously referenced authored texture (**0.564s**). Its visual comparison was **skipped**, because the required isolated fixture flags were missing. That containing run is not visual evidence. The earlier `PiyaliExplorationBuild1.xcresult` failed compilation on combined `@State` declarations; those declarations were corrected before the successful build.

The source comparison fixture rehydrates original exported world/quest data, limits the supplied quest to its search chapter, and mounts the actual `GameRouter`/legacy component. Web character movement, opening dialogue, examining a prop and opening inventory use original controls. Network, account, voice and relay I/O are inert. This is public scenario input for renderer comparison, not evidence that live generation emitted an object-search chapter or that a normal root-product launch reached it.

## Remaining boundaries

Legacy generation still uses the earlier native setting/quest service and a bounded exported template topology. It does not yet execute the source's complete generation, performance-context, dynamic-choice, bridge or fallback policies. Generation failure/cancellation, the source fallback route from the main product, other target languages and a normal product entry/exit journey need explicit work. The older form-oriented `ExplorationPlayTests` use a retired tab/navigation path and are not current product verification.

Legacy room art currently includes the original fixed ground, tiles and props; source ambient layers, lighting/motes, dynamic generated item visuals and exact color/motion compositing remain open. Native legacy casts retain saved character names and use a stable source-art appearance/portrait fallback; the source’s random cast/name-remapping policy remains open. Inventory comparison supplies the native persistent item state; the web fixture acquires it through original controls. The web’s transient pickup/observation cards behind that modal are not recreated in the native comparison input. Those captures do not establish all transient layers. Existing authored environment behavior is preserved. Search/component captures alone cannot establish full map fidelity, all dialogue transitions, arbitrary generated worlds, physical-device microphone/playback or accessibility parity. Broader product scope remains in `PARITY_AUDIT.md`.

Comparison attempts are kept distinct. `PiyaliExploration3.xcresult` failed the new source fixture because its original legacy question table was omitted; its **eight existing authored-world/panel pairs passed in 60.367s** and its legacy texture check passed in **3.366s**. The exporter now retains that original table. `PiyaliExploration4.xcresult` reached the world and dialogue but failed an overly narrow test assumption that a searchable prop would be immediately beside the NPC. The fixture now walks a collision-free route to a real prop before searching. `PiyaliExploration5.xcresult` failed test compilation on an asynchronous call inside an XCTest autoclosure; the values are now awaited before assertion.

`PiyaliExploration6.xcresult` passes all three selected app checks without skips: six source/native legacy component pairs (**65.894s**), all legacy textures (**1.749s**) and the two existing bilingual authored-observation pairs (**15.019s**). Visual review of that run still found a clipped native dialogue body despite the screenshot test passing. Its captures are superseded by the subsequent height/visibility correction; they do not establish acceptable dialogue presentation. The source inventory capture also now waits for the original modal animation to settle. A native label/scroll-viewport assertion was added to catch the previously missed clipping.

`PiyaliExploration7.xcresult` passes all three selected app checks without failures or skips: the six original-renderer/native pairs with explicit visible-label/scroll assertions (**66.394s**), legacy textures (**1.718s**) and both authored-observation pairs (**14.807s**). The 18 current capture/metrics records in `docs/reference/exploration-captures.json` come from this run, have verified hashes, and were visually inspected in English and Arabic. The dialogue is visible and bounded; cast identity, HUD borders, inventory sizing/color and ambient effects still differ. This is not a pixel-identity claim.

The final `PiyaliExploration8.xcresult` build additionally passes all three selected checks without skips: old/new legacy room and item lookup (**3.543s**), distinct connected-room identities sharing one geometry (**1.115s**) and every referenced authored texture (**0.529s**). The renderer now includes room identity in its rebuild key. Presentation captures remain from run 7; this final change only affects transitions between rooms, and the pending-success correction only affects an acknowledged search. No backend deployment or reference edits were made.

The final Swift package selection rechecks all **nine exploration tests** against the final source in **25.713s** (no failures), including a serialized successful hand-in after the dialogue has been closed. Closing/reopening and repeated completion cannot leave it pending or advance twice. The initial nine-test result of 25.701s precedes that stronger closed-dialogue input.
