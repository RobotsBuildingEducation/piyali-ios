# Daily immersion and Score

The native Immersion & Score screen ports the main route's daily checklist, rather than rewarding an arbitrary reflection. A starting-level placement is required for the current language. Three missions refresh at local midnight; an active personal goal adds a fourth. Changing or removing the goal keeps the original three missions and their completions. An untouched older-generation/pre-placement batch refreshes, while a started batch is retained, matching the reference hook.

Generation uses the dedicated Cloudflare Responses endpoint with the configured `gpt-6-luna` model and medium reasoning. It includes Score evidence, the original capability landmarks, a compact summary of the further regular/tutor lesson and the last 24 tasks for that language. The original coaching instructions require short, private, independently doable activities using familiar home/digital resources. They prohibit travel, purchases, accounts, public posting and dependence on strangers. Responses must contain the exact task count, distinct titles and no recent duplicate. The UI offers a retry after generation failure. Goal changes request only the new fourth task.

The shared fields are `realWorldTasks`, `realWorldTaskHistoryByLanguage` and `xpAwardReceipts`. The web receipt is `daily-immersion:<language>:<local day>`. Completing the whole checklist grants **15 XP once**, with no Score assessment or course completion. Undoing/rechecking a task or changing the goal cannot grant it again. A completed but unrewarded restored batch claims its reward on opening. Private reflections remain notes and grant no XP.

Native operations use an offline outbox and Firestore transactions. The first valid batch for the same scope wins. Completion edits bind to the stored batch timestamp and exact task, and per-index timestamps protect against stale edits while allowing different devices to complete different tasks. A new goal arriving before an offline batch's first upload retains its practiced base missions and any already-earned daily reward. Each reward also has a permanent native receipt. Root timestamps are converted individually, so unrelated Firestore timestamps cannot erase checklist data. Acknowledgments replay work performed while upload was in flight.

Accepted tasks/checklists write stable completion events to the private achievement ledger. These survive day/language changes and support the same permanent immersion trophies as the web app. The native evaluator accepts both array and legacy object completion flags. No new rules or external route is needed.

`scripts/export-immersion-fixtures.mjs` reads the reference only and exports the original coaching instructions/Score landmarks and pure behavior fixtures. Core tests compare 21 checklist states, nine quality checks, four history merges, six next-lesson selections and the concise lesson summary. Simulator contracts exercise concurrent edits, stale tasks, web reward receipts, retries, legacy XP preservation and first-upload goal changes. An isolated UI fixture requires both `PIYALI_OFFLINE_TESTS=1` and `PIYALI_IMMERSION_FIXTURE=1`; it never supplies missions in release builds.

The opt-in native live-generation test passed against the deployed API. It uses a temporary Nostr/Firebase Auth identity, two bounded Responses requests and no Firestore writes or subscription grants. The generated Auth account is deleted afterward.
