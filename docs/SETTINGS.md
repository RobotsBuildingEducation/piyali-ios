# Settings and Account correction

The generic account form is replaced at the main product menu by the source's bottom drawer and centered Settings, Account and Subscription tabs. Its close button and tabs scroll with the source body; the drag handle and native keyboard dismissal stay reachable. The native drawer uses the original copy, language options, circular flags, paper/midnight colors, goals field, preference order and source-sized cards. The source renders read-only through the extracted actual TopBar JSX and its original child components; account/provider I/O uses declared public fixtures. Settings screenshots block external provider and relay traffic.

Settings edits save automatically. The persona uses the source's 400 ms debounce, 240 UTF-16-unit cap and three-second Saved indicator, flushing on blur/close. Changing support language localizes only a default persona and preserves a custom one. Goals keep their existing per-account/per-practice-language editor and durable synchronization. Placement opens the existing main-product placement flow.

The native learner currently uses OpenAI WebRTC, so this drawer follows the source's OpenAI voice profile (Cedar/Marin and 200–4,000 ms pause), with the actual source preview text and receive-only narration session. Preview stops on close, language change and account change. Both source provider metadata profiles are exported, but this checkpoint does not implement the web's current default Gemini learner transport or its volume control.

Sound preferences control the quest sounds that exist in the native app. The Allow posts preference now controls automatic progress publication: the first confirmed cloud snapshot establishes a baseline; only a later confirmed root XP increase can publish, with a locally held key and the preference enabled. Account switching and opt-out cancel pending publication. Private fixture tests use only an injected loopback relay; they cannot publish to public relays.

Account has ID copy, device-authenticated/expiring private-key copy, display-name editing with the original signed Nostr kind-0 name/about update, validated secret-key switching, the native remote signer, wallet entry, installed-app/key guidance and confirmed sign-out. Invalid public/private keys leave the current account intact. A profile-publish failure preserves the name, and a late acknowledgment cannot rename another account. Empty names show the source warning. Wallet contents still use the existing native wallet screen; the source wallet accordion design is not yet ported. Installed-app guidance is a platform adaptation of the web installation section.

Preferences use canonical partial Firestore transactions and durable receipt IDs. Each retry evaluates the source normalizer against the latest settings and writes only settings fields. It preserves XP, entitlements, foreign nested values and their Firestore types. Acknowledgment replays newer offline edits; settings do not award XP or write private native snapshot copies of canonical settings.

The unlinked subscription panel now uses the actual embedded benefits/membership offer rather than the full-page gate header. The web payment link, Apple products when available, refresh and restore use the real existing subscription service. Full Patreon linked/payment/replacement/disconnect presentation and real paid-member/App Store verification remain separate unfinished work; the offer render alone does not establish payment parity.

## Verification

The exporter executes 258 actual source normalization, persona, provider-voice and preview cases. The complete 288-test Core suite passes. Native settings/controller tests cover signed profile metadata and account fencing, normalization, invalid-key scope, default/custom persona language changes and automatic posts over a validating loopback relay. A real Firestore SDK emulator race checks concurrent voice/pause edits, acknowledgment with a newer offline edit, preserved XP/entitlement and preserved foreign timestamp/blob values. Product journeys and final source/native captures are recorded in [VALIDATION.md](VALIDATION.md).

The Arabic posts dialog keeps a readable dark surface. The actual source WebKit capture currently shows a white surface with faint text in that state. Native menu/slider presentation and backdrop blur outside the drawer remain platform differences.

Remaining work includes Gemini learner transport/volume, other UI sounds, source wallet contents, all subscription states, additional locales/text sizes, native menu/slider differences, exact motion and physical-device voice/key authentication. This checkpoint does not complete the overall parity audit.
